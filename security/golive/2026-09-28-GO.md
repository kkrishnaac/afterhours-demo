## What changed since 2026-09-24

- Redesign and rename to HARA. GSAP removed; page JS is ~10 KB gzip (Lenis + own modules).
- Icons (Phosphor, MIT) and `<picture>` markup are expanded into static HTML at build time by a
  Vite plugin (`vite.config.js`), so no runtime HTML building.
- New content: flexible-hours schedule grid, security practices section, service lists
  (`<details>`), walkthrough request form (adds an optional phone field). The form is still
  DEMO ONLY: `src/quote.js` prevents submit and sends nothing.
- Build now injects a font `<link rel="preload">` (same-origin asset).

## Attack surface (Phase 1)

- Routes: one static page (`index.html`) plus same-origin assets (`assets/*.js|css|woff2`,
  `img/*`, `favicon.svg`, `og.jpg`). All public by design. No endpoints.
- Input: the walkthrough form (size, timing, city, name, email, phone). Values never leave the
  browser; the first name is echoed back with `textContent` (`src/quote.js`), never HTML.
- Outbound: none. Only `tel:` and `mailto:` links. No fetch/XHR/beacon/WebSocket in `src/`.
- Storage: none (no cookies, localStorage or sessionStorage).

## Adversarial pass (Phase 3)

1. **Browser and URL only:** view-source shows nothing secret; the form sends nothing; there
   is no hash routing or query parsing to abuse. In-page links use `querySelector` on the site's
   own `href`s only.
2. **Change an ID:** there are no IDs or requests.
3. **What does it trust from the client:** nothing is sent anywhere, so nothing is trusted.
4. **Hostile user:** no accounts, no state, nothing to escalate.

## FIX BEFORE THE REAL LAUNCH (not blocking this demo)

- **[UNLISTED, legal] Security claims are unverified.** The "Trusted with your keys" section
  describes practices (key/fob sign-out, alarm codes limited to assigned staff, a consistent
  team, visit logs, lock-up checks). They are written as promises. The client must confirm each
  one is true before launch, or it becomes a misrepresentation risk.
- **[T47] Clickjacking and MIME-sniffing headers.** Meta CSP cannot set `frame-ancestors`.
  Low risk today (no state-changing actions). The real site should move to a host that sends
  headers (Cloudflare Pages / Netlify / Vercel) with `frame-ancestors 'none'`,
  `X-Content-Type-Options: nosniff`, and the CSP as a header.
- **[T16/T28/T35, future]** When the walkthrough form gets a backend: server-side validation,
  rate limiting and spam protection, no PII in logs, plus `build-security` Part B (PIPEDA
  privacy policy linked at the form, CASL wording if any follow-up marketing).
- **Placeholders:** phone and email are placeholders; `noindex` must be removed at launch.

Legal exposure (privacy policy, PIPEDA, CASL, AODA, image licensing for the generated stills) is
not covered by this gate; run `build-security` Part B before the real launch.
