## Attack surface (Phase 1)

| Surface | Access | Protection |
|---|---|---|
| Pages and assets (`dist/` via `env.ASSETS`) | Public | Static; security headers from `dist/_headers`; unknown paths 404 |
| `POST /api/walkthrough` | Public, anonymous (by design) | Origin allowlist, JSON-only, 8 KB cap, 5/min per IP, schema allowlist, honeypot, Turnstile verified server-side (hostname + action), parameterised D1 writes |
| Any other `/api/*` | Public | JSON 404 (`worker/index.js:28`) |
| Cron (every 15 min) | Not reachable over HTTP | Retries held/failed notifications, deletes rows past 730 days |
| D1 `walkthrough_requests` (name, email, phone, city, choices, consent) | Worker binding only; people read it only through the Cloudflare account (`npm run leads`, dashboard) | No HTTP read path exists |
| Outbound | Turnstile siteverify, Resend (fixed URLs, not user-controlled) | Server-held secrets |
| Browser third party | `challenges.cloudflare.com` (Turnstile widget, last form step only) | CSP allows only this origin |

Inputs: JSON body fields (`size`, `timing`, `city`, `name`, `email`, `phone`, `marketing`,
`company_site` honeypot, `turnstile`), headers `Origin`, `Content-Type`, `Content-Length`,
`CF-Connecting-IP` (set by Cloudflare). No uploads, no URL parameters used, no cookies.

## WARNINGS: fix before the next release

- **[T28 / UNLISTED] The body is read before the rate limit.** `worker/walkthrough.js:32-39`
  reads the body (`readLimited`) and only then calls the limiter, and `worker/http.js:21-26`
  buffers the whole body when no `Content-Length` is sent. Verified live: while rate limited,
  a 200 KB chunked POST got 413, not 429. Impact is limited (Cloudflare's body cap and the
  Worker's CPU limit end the request), but an attacker can make the Worker read large bodies
  without ever hitting the limiter. FIX: call the limiter before reading the body, and read the
  stream with a running byte count that stops at 8 KB.
- **[T37] 4 moderate advisories, dev tooling only:** `undici` inside `miniflare` (used by
  `wrangler` and `@cloudflare/vitest-plugin` for local runs and tests). Not in the deployed
  Worker. Update when a fixed `wrangler` ships. Production dependencies: 0 vulnerabilities.
- **[T42] No read-access trail.** Every request row carries `created_at`, and Cloudflare's
  account audit log records account actions, but the app cannot say who looked at a lead and
  when. Acceptable at this size; revisit if a staff dashboard is built.
- **[T13] The repository is public by choice.** No secret is in any commit (checked below), and
  client documents are gitignored. Consider making it private; note that the GitHub Pages
  redirect page needs a public repo on a free plan.

## UNLISTED NOTES (not findings)

- The Origin check is not authentication: a script can send any `Origin`. It exists to stop
  cross-site form posts; Turnstile is the real gate, and it is verified server-side.
- Names may contain `<` and `"` (people's names can). They are escaped in the HTML emails
  (`worker/email.js:12`) and are never rendered on the site.

## Fixes and stress tests (same evening): GO

- **[T28] Fixed.** The rate limit now runs before the body is read (`worker/walkthrough.js`),
  and `readLimited` (`worker/http.js`) reads the stream with a running count and cancels just
  past 8 KB. Tests: a 4 MB chunked body is refused after a few 4 KB chunks; a limited visitor
  sending a large body gets 429, not 413.
- **UNLISTED, fixed: double-submit race.** Stress test: 20 simultaneous submissions from one
  person stored 20 rows (the duplicate check was a SELECT followed by an INSERT). The check and
  the insert are now one `INSERT ... SELECT ... WHERE NOT EXISTS` statement; the same test stores
  1 row. This also closes the race on the 2-per-day confirmation-email cap.
- **UNLISTED, fixed: form could skip a step.** A chip click auto-advances after 260 ms; pressing
  Next inside that window advanced twice and skipped the timing question (`src/quote.js`). The
  timer now advances only from the step it was started on.
- **[T37] Cleared.** `undici` pinned to a patched 7.x through `overrides` (GHSA-3wwx-pv8p-q78v);
  `npm audit` (all dependencies, dev included): 0 vulnerabilities. vite 8.3.1, sharp 0.35.5.
- **[T44] Restore rehearsed.** Point-in-time restore and export/import both worked on a scratch
